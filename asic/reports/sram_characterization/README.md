# SRAM Liberty Re-characterization Report

## Scope and safety gates

This work characterizes the existing transistor-level SPICE views without
modifying the approved GDS, LEF, Verilog, SPICE, or existing Liberty files.
New Liberty files are written only below each macro's
`lib_recharacterized/` directory.

The mandatory 1 KiB pilot is a hard gate. `scripts/recharacterize_sram.py`
refuses both 2 KiB phases unless it is given a reviewed JSON acceptance marker
covering the matching TT pilot corner and the exact OpenRAM commit. No 2 KiB
characterization has been run yet.

the host and project devshell unchanged while keeping the run reproducible.

## Characterization phases

- `pilot`: project 1 KiB `32x256`, official 3x3 slew/load grid, TT at 1.8 V
  and 25 C. Results are compared against the only PDK Liberty belonging to
  this exact physical macro.
- `a1`: 2 KiB `32x512`, unchanged 3x3 grid at SS/1.60 V/100 C,
  TT/1.80 V/25 C, and FF/1.95 V/-40 C.
- `a2`: DDK-approved 2 KiB 7x7 extended grid. These generated models may be
  used for synthesis, placement, routing, and timing optimization. They are
  not final signoff models: post-PnR signoff STA must be rerun with the
  reference PDK Liberty and both result sets must be reported separately.

The baseline axes reproduce the official PDK values exactly:

- slew: `0.00125, 0.005, 0.04` ns
- load: `0.0017225, 0.00689, 0.02756` pF

## Existing-netlist compatibility checks

The current PDK macro SPICE hierarchy is one level shorter than the default
probe hierarchy generated by OpenRAM v1.2.48. The unmodified defaults probe
two nonexistent paths:

- `X<macro>.xbank0.s_en0` instead of `X<macro>.s_en0`
- a bitcell path containing a nonexistent `xreplica_bitcell_array` instance

This caused the first pilot attempt's Q/Q_bar and sense-enable measurements to
fail. OpenRAM interpreted the failed functional check as insufficient clock
period and repeatedly doubled 10 ns to 20, 40, and 80 ns.

The current PDK SPICE macro also declares vector ports MSB-first, whereas the
generic v1.2.48 memchar stimulus instantiates them LSB-first. Since SPICE
subcircuit ports are positional, the original stimulus connected logical bit
31 to physical bit 0 while the internal probe observed physical bit 31. The
wrapper now parses the top `.SUBCKT`, translates every formal pin to its
stimulus net, requires an exact pin-set match, and instantiates in the published
order.  This is not inferred from the historical functional stimulus: the
2021 upstream source netlist used LSB-first ports.  The installed PDK netlist
is a later `LVS: True` view with MSB-first ports and updated bitcell devices;
its SHA-256 matches the SPICE file copied into this project.

`scripts/openram_existing_sram_char.py` now validates the exact subcircuit
chain before applying probe templates for the installed netlist. The matching
project-macro TT reference reports a 1.791 ns minimum period, but its preserved
generation log proves that OpenRAM v1.1.15 produced it with the analytical
Elmore model (`analytical_delay=True`), not SPICE simulation. Its 1.791 ns
value is therefore a reference-model constraint, not an independently measured
functional limit for the current transistor netlist. SPICE feasibility at 2 ns
and 4 ns both failed because the selected cell did not complete the write-one
operation. The failure is being localized with internal control/bitline
measurements before any Liberty is accepted.

The previously considered `sram_1rw1r_32_256_8_sky130_{SS,FF}` files are not
references for this pilot: they describe a different physical implementation
(area 167998.55 versus 190712.55 and a different interface). Their reported
0.131/0.107 ns minimum periods must not be attributed to the project macro.

## Netlist trimming

Timing characterization uses OpenRAM's standard row/column trimming; leakage
uses the complete netlist. The upstream v1.2.48 trimmer expects older names
such as `wl0_127`, while these macros use `wl_0_127`. The compatibility wrapper
accepts both forms and aborts if the selected real-array bitcell is not
preserved exactly once.

For the 1 KiB pilot, trimming reduced the transistor/subcircuit-instance lines
from 9,525 to 1,333 (86.0%). It retained the selected row and column union in
the main array (191 cells), plus the relevant dummy/replica load cells. This
preserves the wordline and bitline loading on the measured path while removing
inactive rows and columns. Because the SPICE view is not an extracted RC
netlist, this method does not claim to model layout coupling; its purpose is to
retain the schematic electrical loads used by OpenRAM while making simulation
tractable. The full source remains in use for leakage measurement.

## Pilot comparison

Pending a clean TT rerun after the failed-write diagnosis. A successful pilot
automatically compares the generated
`sky130_sram_1kbyte_1rw1r_32x256_8_TT_1p8V_25C.lib` against the matching PDK
file and writes an arc-level JSON report under
`reports/sram_characterization/comparisons/pilot_3x3/`. Because that PDK file
is analytical while the candidate is simulated, the report will quantify and
explain numerical differences rather than treating bit-for-bit equality as a
valid acceptance criterion.

## Commands

Pilot:

```bash
python3 scripts/recharacterize_sram.py \
  --phase pilot \
  --parallel-corners 1 \
  --sim-threads 4 \
  --openram-dir /tmp/openram-char.uPnbHR/OpenRAM
```

A1 and A2 remain gated and are intentionally not listed as ready-to-run main
flow commands until the pilot comparison is reviewed. Once accepted, A2 is a
PnR optimization model only; final signoff always returns to the reference PDK
Liberty and reports that STA separately.
